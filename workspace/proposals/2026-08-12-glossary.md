# Proposal: add a follow-up vocabulary glossary to docs/

**Why.** On 2026-08-12 the agent received "drop SLED to the historic floor and any
territories that don't have existing pipe drop the historic floor" and, unable to
map the shorthand onto anything in the corpus, substituted a verification of the
unchanged run for the requested scenario re-solve. Conversational shorthand needs
something in the corpus to resolve against.

**Proposed new file `docs/glossary.md`** (and a routing row in `docs/README.md`'s
task→file map: "shorthand / follow-up phrasing → glossary.md"):

```markdown
# Glossary — conversational shorthand → model terms

| Shorthand | Means |
|---|---|
| "SLED", "Enterprise", … | Territory names (BTS_Territory values). Resolve against the current run's Territory column; ask if no match. |
| "drop/clamp X to the floor" | Override: set pipe_create_target = historic_floor for that territory (binding = floor), then re-total. |
| "drop/remove the floor" | Override: pipe_create_target = required_by_gap (the clamp in Step 5 is not applied). |
| "existing pipe", "no pipe" | The expected_from_existing_pipe term. "No existing pipe" = that term is 0 for the row. |
| "the target" (unqualified, in a follow-up) | The most recent run's derived pipe create target, at its grain. |
| "In Q" / "Pre Q" | The two win rates and the two slip timings. Never "later rate". |

Scenario overrides are derive-side work: re-solve via a scratch script importing
`pipeline.derive.derive_frame`, record a run, report before/after per affected
territory.
```

**Not included on purpose:** a full territory list — it would go stale; the run
CSV is always the live source of names.
